# 計測の一覧

この道具について、何を測ったか、数字がどこにあるか、何をまだ測って
いないかを、1 か所にまとめます。数字の表そのものは、それぞれの文書に
あります。ここには、条件と主な値だけを写しています。食い違っていたら、
リンク先の文書が正です。

確度の表記: 【実測】手元で測った / 【未確認】確かめていない。

## 先に結論

- 測ったのは、部品ごとの性質です。索引づくりの時間と大きさ、検索 1 回の
  時間、当たりの割合、Copilot CLI で仕組みが通ること【実測】
- 題材は、公開されているコード(O3DE と Godot)と、合成のコーパス
  (`tests/fixtures`)だけです
- 行の範囲で正解を付けた評価は、公開されているコード 2 つで行いました。
  検索だけの手法(既定の hybrid)で、上位 5 件に根拠が入った質問は、O3DE の
  評価例([examples/o3de](../examples/o3de/README.md))で 54%、Godot で
  50.0% です。どちらも、目安の 80% に届いていません。検索時間は、目安の
  内側です【実測】
- Godot の同じ質問で、既存の手順(grep だけ)と、この道具を足した手順を
  3 回ずつ比べました。回答の合格率は 79.3% と 78.2%、時間と費用の中央値は
  ほぼ同じで、差は出ていません。この道具を足した手順で、検索の結果が
  返ったのは 87 回のうち 42 回でした【実測。採点は AI】
- 事前に決めた目安では、Godot での候補の 2 つ(`hybrid` と `agent_cf`)は、
  どちらも不合格です。使う人自身のコーパス(実コーパス)での比較は、
  行っていません
- そのあと、エージェントへの出し方を、skill から「MCP サーバーと、検索を
  先に使うように促す始めの 1 文」に変えました(0.3)。Godot の調整用の
  7 問では、21 回すべてで検索が使われ、既存の手順に比べて、モデルの
  呼び出しは 5 回から 2 回、入力トークンは半分以下、時間は 10%、費用は
  14% の減でした。評価用の 29 問では、まだ測っていません【実測。回答の
  採点はしていない】

- 調整用と評価用で、正解の広さが違います(1 問あたり約 600 行と約 170 行)。
  用語の対応表も、調整用の質問を見て決めました。調整用の数字は、高めに
  出ます

  読みだけで作りました。36 件のうち 12 件を、別の AI が抜き取りでコードと

  場所、根拠に挙げた場所の順)。Godot の比較では、回答の合格率を使って
